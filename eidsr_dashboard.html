NMCP eIDSR Extract

Purpose. This tool extracts weekly surveillance data reported through the eIDSR (electronic Integrated Disease Surveillance and Response) system — clinical, confirmed-positive and tested malaria — for every health facility in Sierra Leone, cleans it, attaches Public/Private ownership, and produces analysis-ready tables. Every step below is applied automatically on each run.
1
Fetch the facility registry
All Level-5 (PHU) org units are pulled from DHIS2 with their full hierarchy — District (Level 2) and Chiefdom (Level 4).
2
Apply exclusions before any data is fetched
A facility is dropped entirely — appearing in no analysis, denominator, or export — if it is:
  • A laboratory (name contains "Laboratory"). These are not health facilities, yet many are typed Hospital in the source, which would inflate the Hospital count.
  • A Marie Stopes facility — excluded by NMCP request (specialised SRH provider).
  • Of an unrecognised type — the type cannot be derived from the facility name.
Facility types are normalised to five categories: Hospital, Clinic, CHC, CHP, MCHP. Misspellings are folded in ("Climic" → Clinic), as are nursing homes ("Home" → Clinic).
The full list of excluded facilities, with the reason for each, is shown and downloadable after the run.
3
Fetch eIDSR data weekly
eIDSR malaria indicators are reported weekly (ISO epidemiological weeks) through the IDSR Weekly Disease Report dataset. Three data elements are fetched, each split by age group (<5 years / 5+ years) and by cases vs deaths:

3 data elements × 4 category option combos = 12 values fetched per facility per week. Each of the 12 stays split by age group (<5y / 5+y) — the epidemic threshold is computed separately for each of the 12, so an under-5 outbreak is never diluted by combining it with the over-5 numbers.
Unlike monthly HMIS forms, eIDSR periods are ISO weeks (Monday–Sunday), coded as YYYYWn (e.g. 2026W5). A year has 52 or 53 such weeks depending on where 1 January falls.
4
Attach ownership (Public / Private)
Each facility is matched to the NMCP PHU ownership master list, in this order:
  1. DHIS2 OU ID — exact, and immune to renames or spelling changes
  2. Chiefdom (Level 4) + Facility name (Level 5)
  3. Facility name alone
Matching on name alone cannot separate two different facilities that share the same name in different chiefdoms — the OU ID match resolves each one exactly, and keeps working even if NMCP later renames a facility.
5
Classify facilities as Active or Inactive
  • Active — reported at least one eIDSR value during the selected period.
  • Inactive — present in the DHIS2 registry but reported no eIDSR data at all for the period.
Only active facilities are used as the denominator in the reporting rates below — an inactive facility is an existence problem, not a reporting-behaviour problem, and separating the two keeps both measurable.
6
Build a complete period grid
For every active facility, a row is created for every week of the selected range — including weeks with no data. Those appear explicitly with Reported = No rather than silently disappearing, so reporting gaps are visible and countable.
7
Calculate reporting rates
Reporting rate = (facilities reporting eIDSR that week ÷ ACTIVE facilities in that group) × 100
Computed per week, broken down by ownership (Public vs Private) and by facility type (CHC, CHP, MCHP, Hospital, Clinic).
8
Compute epidemic thresholds mean + SD
Applied independently to each active facility × each of 12 series (Clinical / Confirmed Positive / Tested, each split into <5y and 5+y, each split into Cases and Deaths). Only reported weeks are used to build the baseline.
Alert threshold = mean + 2 × SD  ·  Epidemic threshold = mean + 3 × SD
  • Needs at least 2 reported weeks for that facility-series; below that, no threshold is computed.
  • A week is flagged Alert if it exceeds the 2‑SD line but not the 3‑SD line, and Epidemic if it exceeds the 3‑SD line.
Which to use — 2 SD or 3 SD? Both, as a two-tier system, which is how this is normally used in IDSR-style surveillance: 2 SD (Alert) is the standard early-warning line — sensitive enough to prompt a look before things escalate. 3 SD (Epidemic) is the stricter, more specific confirmation line — fewer false alarms, but it triggers later. If you only want one number, 2 SD is the generally recommended default; use 3 SD if a facility's baseline is noisy and 2 SD flags too often.
9
Produce the outputs
Each of the 12 series carries five columns, in this order:
  • Value — the raw weekly total for that series (cases or deaths, for that condition)
  • Baseline Mean and Baseline SD — that facility-series' own history across the selected period
  • Alert Threshold (2SD) and Epidemic Threshold (3SD)
  • Epidemic Status — Normal / Alert / Epidemic, or blank if there weren't enough reported weeks to compute a baseline
Plus Reported. The Epidemic Threshold tab lets you pick a facility and condition and see cases and deaths plotted against their Alert/Epidemic lines over time, filterable by district, chiefdom and facility. Other analyses include weekly reporting rates by ownership and facility type, facility activity, excluded facilities, yearly Public vs Private totals, and an ownership reconciliation — all downloadable as CSV or Excel.

Method — mean + standard deviation ("epidemic channel")
For each active facility, separately for each condition (Clinical Malaria, Confirmed Positive Malaria, Malaria Tested) and separately for cases and deaths, the mean and standard deviation of that facility's weekly counts across the selected period set two thresholds:
Alert threshold = mean + 2 × SD  ·  Epidemic threshold = mean + 3 × SD
A week is flagged Alert if the value exceeds the 2‑SD line but not the 3‑SD line, and Epidemic if it exceeds the 3‑SD line. Needs at least 2 reported weeks for that facility-series to compute a threshold at all; below that, nothing is flagged — with very few weeks the line is shown but should be read as tentative.
Which to use? Rather than picking one, both are shown as a two-tier system, which is how this is normally used in IDSR-style surveillance: 2 SD (Alert) is the standard early-warning line — sensitive enough to prompt a look before things escalate. 3 SD (Epidemic) is the stricter, more specific confirmation line — fewer false alarms, but it triggers later. If you only want one number, 2 SD is the generally recommended default for a first alert; use 3 SD if the facility's baseline is noisy and 2 SD is flagging too often.
